# 개인 서버 P2 보안 작업 계획

작성일: 2026-06-10

## 현재 완료

- 업로드 파일 확장자, MIME, 용량, 파일 헤더 검증 유지
- ClamAV 기반 로컬 악성코드 스캔 연동
- 로컬 업로드 파일 짧은 만료 서명 URL 적용
- 업로드 파일 라우트 권한 확인 및 private cache 적용
- 민감정보 마스킹 공통 유틸 추가
- 주요 보안 이벤트 감사 로그 추가
- `user.role == "admin"` 기준 관리자 guard 보강

## 서버 확정 전 진행 가능한 범위

- 애플리케이션 로그 마스킹
- 관리자/일반 사용자 권한 분리
- 접근 감사 로그 저장
- TLS/Nginx 설정 템플릿 작성
- UFW 방화벽 적용 스크립트 작성
- 백업 산출물 암호화 스크립트 작성

## 서버 확정 후 필요한 입력

- 운영 도메인
- 개인 서버 공인 IP
- 앱 내부 포트
- SSH 허용 CIDR 또는 VPN/Tailscale 사용 여부
- Let's Encrypt 인증서 발급 이메일
- `RUNNINGMATE_FILE_URL_SECRET`
- DB 계정/비밀번호와 백업 계정 정보
- 백업 암호화 passphrase 파일 경로

## 권장 방화벽 정책

| 대상 | 정책 |
| --- | --- |
| 80/tcp | 전체 공개, 인증서 발급 및 HTTP to HTTPS redirect |
| 443/tcp | 전체 공개 |
| 22/tcp | 운영자 고정 IP 또는 VPN CIDR만 허용 |
| DB 포트 | 외부 차단 |
| 앱 내부 포트 | 127.0.0.1에서만 접근 |

## 권장 암호화 정책

1. 백업 산출물 암호화: 즉시 적용 가능
2. 업로드/데이터 디렉터리 권한 700, 파일 600
3. 서버 디스크/볼륨 암호화: 서버 생성 단계에서 적용 권장
4. 일기/민감 기록 앱 레벨 암호화: 별도 키 운용 정책 확정 후 진행

## 검증 체크리스트

- HTTP 접속이 HTTPS로 리다이렉트되는지 확인
- TLS 인증서가 유효하고 HSTS가 적용되는지 확인
- SSH가 허용 CIDR 밖에서 차단되는지 확인
- DB 포트가 외부에서 닫혀 있는지 확인
- `/api/run-images`, `/api/run-media` 원본 URL 직접 접근이 차단되는지 확인
- 만료된 서명 URL이 차단되는지 확인
- `security_audit.jsonl`에 민감정보가 원문으로 남지 않는지 확인
- 백업 암호화 파일 복호화 리허설 성공 여부 확인
